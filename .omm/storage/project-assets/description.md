Persists media payloads, writes manifests, diagnoses missing assets, relinks files, validates external bundles, and maps node fields to durable project files.

Cloud project media preparation is being built separately: verified local node bindings become deduplicated opaque cloud references, and verified downloaded assets can be rebound to the destination's local paths. Main-process staging restricts files to trusted roots and snapshots them in a private temporary directory. Account-scoped transfers and metadata operations are bounded by the login lifecycle; download checks length and SHA-256. The IPC bridge is enabled by default with an explicit local kill switch; the account panel advertises sync only after an authenticated quota endpoint probe, hides it when the server does not support it, and offers retry on transient failure. The bridge permits only assets in the saved project's complete reference manifest and managed project/shared-blob roots, runs the shared safety guard on project state, and writes downloaded assets via exclusive content-addressed publication without overwriting existing files. It exposes no credentials or arbitrary filesystem root. The account panel coordinates saved-project upload and restoration as a new project using the existing storage write barrier and rollback transaction. Synthetic tests cover idempotent retries, asset validation, and preservation of the original project. Non-bound asset forms, production data and backup, final native UI end-to-end verification and rollout remain required before release.

Legacy IndexedDB-backed `*Ref` media can be found recursively, checked against any hydrated value and converted into opaque hash references. The main-process bridge stages renderer-provided bytes privately, checks their SHA-256 and account lifecycle, and transfers them without accepting renderer filesystem paths. Restore verifies downloaded bytes, writes fresh destination-project references and data alongside the project in the existing rollback transaction. Unsupported formats fail closed rather than pretending to sync.

The portable path also recognizes bindings whose only backing is `portableDataRef`, including when no corresponding `*Ref` field exists. Such bindings are converted to opaque references with restricted metadata and reconstructed with fresh IndexedDB keys on restore; conflicts and missing content fail before snapshot upload.

Chunk helpers decode and reconstruct legacy base64 in bounded chunks and stage them in the main process with sequential offsets, account guard, hash, private file identity and cleanup. The sync coordinator uses session-bound chunked upload and download above 128 MiB. Legacy data URLs remain bounded just below 384 MiB of raw bytes because their representation requires one JavaScript string; file-backed media follows a separate streaming path. Tests include a 129 MiB synthetic client roundtrip through a real isolated account HTTP service on Windows Ubuntu, and reduced-threshold real Electron/IndexedDB tests. The client in the large test ran in a Linux container with a synthetic Windows device identity; actual large-file production HTTP, Windows packaged GUI, fully native cross-device delivery, installation and release remain unverified.

Renderer chunk decoding and reconstruction periodically yield to the event loop; an isolated scheduling test confirms other queued work can run during processing. This is not a measured guarantee of smooth rendering on every device.

For the next coordinated account-service and client candidate, uploads larger than 32 MiB use separate HTTP requests of at most 32 MiB under one account-scoped blob reservation. The server serializes writes with its existing storage lock, checks sequential offsets and identical replays, verifies the entire blob hash before publishing and charging quota, and removes expired partial files during reservation recovery. The old single-request endpoint remains for smaller assets. Source-level tests use a synthetic edge limit and an isolated FastAPI/store implementation; real PostgreSQL, the final service image, packaged clients and the public Cloudflare route still require end-to-end qualification before rollout.
